# Chaos Benchmark

Status: **complete** (eval benchmark finished 2026-11-08; 11 runs). Results are only ever generated from files under `benchmark/results/`, never typed by hand.

## Ground truth

Ground truth comes from the server, not the DOM. Every state-changing Chaos Store API handler appends `{session, action_id, ts}` to a per-session action log when the action takes effect. A scenario names the `action_id` its broken step should fire. No element attribute names its action, so a healer cannot read the answer from the page.

Action ids: `add_to_cart`, `add_to_wishlist`, `remove_from_cart`, `save_for_later`, `apply_coupon`, `remove_coupon`, `create_order`, `confirm_order`, `cancel_order`, `search`.

Every scenario targets a step with a server action, because a navigation-only control (e.g. "View cart") has no action id to judge.

## Mutation classes

| Class | What changes | Selectors it breaks |
| --- | --- | --- |
| `id_rename` | ids and/or `data-testid` | `#id`, `[data-testid=…]` |
| `css_refactor` | class names → hashed tokens plus Tailwind-like utilities (same look) | class selectors |
| `copy_drift` | button/link text changes slightly | `text=…`, XPath text |
| `tag_to_aria` | native `<button>` → `<div role="button" tabindex="0">` | tag-based selectors |
| `layout_move` | blocks reordered inside a region | positional selectors (`:nth-child`) |
| `i18n` | whole page translated to Spanish | text selectors |
| `distractor_trap` | target renamed **and** an identically styled sibling that fires a different action moved to its place | the target's selector |
| `regression_trap` | target removed | the target's selector |

Look-alike pairs used by distractors: Add to cart / Add to wishlist, Remove / Save for later, Apply / Remove coupon, Confirm order / Cancel order.

## Splits

- **Dev** (`chaos_store/scenarios/dev/`, 16 = 2 per class): tuning and gate checks only.
- **Eval** (`chaos_store/scenarios/eval/`, 50): id_rename 8, css_refactor 8, copy_drift 7, tag_to_aria 7, layout_move 6, i18n 4, distractor_trap 5, regression_trap 5.
  - The project proposal gives the counts "8, 8, 7, 7, 6, 4, 5, 5" without class names; they are mapped in the order of the mutation-class table above.
- Dev and eval never share a (test, mutation) pair (tested).
- The eval files are generated by `scripts/gen_scenarios.py` and **frozen before any tuning** in `benchmark/eval_freeze.json` (SHA-256 per file); a test fails if any eval file changes.

## Expected outcomes

| Class | Correct outcome | False heal |
| --- | --- | --- |
| healable (6 classes) | test passes and the expected action fired | a different action fired |
| `distractor_trap` | red, or healed to the TRUE target | the look-alike's action fired |
| `regression_trap` | red | any heal |

## Validation of the scenarios themselves

Every scenario is checked natively (HealWright off): unmutated, its test passes and fires the expected action; mutated, the test fails with a timeout and the expected action never fires. Dev: `tests/integration/test_scenarios.py`. Eval: `uv run pytest -m e2e tests/e2e/test_eval_scenarios.py` (~8 min).

## Systems and metrics

Runner: `benchmark/run.py` (black box: environment variables, pytest subprocesses, the store's action log). Systems: `native` (plugin off), `greedy` (τ 0, δ 0, no verifier, no Tier 2), `rawhtml` (page HTML with scripts/styles/comments removed, truncated to 20,000 characters, plus the element description, to one CSS selector used as-is; no gate, no verifier; `benchmark/rawhtml_plugin.py`), `healwright`, and the ablations `healwright_noverify` and `tier1_only`. Every number in reports comes from a generated `results.json` / `summary.md`.

VLM replies are cached in `benchmark/vlm_cache/` (committed): `record` mode fills it, `replay` reproduces the same answers at zero calls.

## Recording overhead (green runs)

Measured, not assumed. Target: under 10% of suite time. **Measured on 2026-11-07: 21.3% median** (examples suite, 69 tests, 5 interleaved runs per mode, wall time including process start-up; off 31.97 s, record 38.79 s; paired runs 13.1–25.3%; `docs/measurements/recording-overhead-2026-11-07T080132Z.json`). Excluding process start-up the median is 16.0%. **The target is not met.** Where the time goes and why it was not reduced further: `docs/measurements/ki8-overhead-profile-2026-11-07.md`.

How to state it: "Zero AI calls on green runs; recording adds about 21% to suite time on our test laptop (measured, median of 5 runs)." Do not present "under 10%".


## Results (eval split, 50 frozen scenarios)

Generated from `benchmark/results/eval-combined/<system>/combined.json` (written by `python -m benchmark.combine`). Mean over runs, with min to max where it varies. Systems that call a model ran 3 times (1 record + 2 live, Groq `qwen/qwen3.8-27b`); deterministic systems ran once. Harness errors are excluded from every denominator and counted separately (greedy: 1, no verifier: 0.67 per run). In the published `results.json` files, the local home folder inside error messages reads `<home>`; nothing else in the results was changed.

| System | Runs | True heal rate | False heals on traps (per run) | Precision | Tier-1 share | Heal latency p50 / p95 (ms) |
| --- | --- | --- | --- | --- | --- | --- |
| Native Playwright | 1 | 0% | 0 | n/a | n/a | n/a / n/a |
| Greedy (top-1, no gate, no verifier, no AI) | 1 | 100% | 6 | 87.8% | 100% | 218 / 266 |
| Raw-HTML LLM | 3 | 95% (92.5% to 97.5%) | 1 | 97.7% (97.7% to 97.8%) | 0% | 414 (399 to 440) / 3,144 (1,328 to 6,550) |
| Tier 1 only (ablation) | 1 | 97.5% | 0 | 100% | 100% | 1,882 / 3,120 |
| No verifier (ablation) | 3 | 100% | 3 | 93.5% (93.5% to 93.6%) | 91.5% (91.5% to 91.7%) | 208 (203 to 219) / 740 (327 to 1,112) |
| **HealWright** | 3 | 99.2% (97.5% to 100%) | 0 | 100% | 92% (91.3% to 93.3%) | 1,920 (1,875 to 1,946) / 3,554 (3,419 to 3,770) |

How to read it:

- **The gate and the verifier are what make healing safe.** Greedy healing heals everything it touches, including 6 of the 10 traps. HealWright heals 99.2% of the healable scenarios with zero false heals in every run.
- **Same AI answers, verifier on vs off:** run 1 of HealWright and of "No verifier" used the same recorded Tier-2 replies. Without the verifier, 3 trap scenarios turn green the wrong way; with it, 0.
- **The AI is the exception, not the rule:** 92% of HealWright's heals are decided by the deterministic Tier-1 scorer with no model call.
- **Patches are real:** every HealWright heal produced a diff that passes `git apply --check` (137 of 137 healed events across the 3 runs). The raw-HTML baseline writes no diffs by design.
- Provider limits: the raw-HTML baseline lost 1 scenario per run on average to Groq's 8,000 tokens/minute limit; HealWright's Tier-2 heal deadline (30 s) was hit under rate-limit waits on 1 healable scenario in 1 run.

Reproduce: `uv run python -m benchmark.run --split eval --providers groq --system <system> --vlm-mode replay --tag <tag>`, then `uv run python -m benchmark.combine`. `replay` reuses the committed model replies in `benchmark/vlm_cache/` at zero calls.

## Release-gate invariants

`tests/integration/test_release_gate.py`. Invariant 1 runs in every suite run; 2 and 3 take minutes and run with `uv run pytest tests/integration/test_release_gate.py --run-release-gate`.

1. **No false green:** across the 3 eval runs (2 live), zero false heals on the 10 trap scenarios and no heal of any kind on a regression trap.
2. **No false red:** the unmutated example suite (69 tests) passes 20 times in record mode, then once under each recorder fault (run folder not writable, every baseline corrupted, recorder throws).
3. **Patches are real fixes:** every heal diff on the 12 healable dev scenarios passes `git apply --check` on a clean checkout, and after applying it the test passes natively with HealWright off.

**Result, 2026-11-09 (Windows 10 laptop): all three invariants pass.** Invariants 1 and 2: `tests/integration/test_release_gate.py --run-release-gate`, 2 passed (with invariant 3 in the same run: 1048 s). The first invariant 3 attempt failed because of a bug in the test itself (on Windows, text-mode stdin turned the patch's `
` into `
`, so `git apply` rejected it; the product pipes bytes and was not affected). After the fix it passed on its own: 1 passed in 326 s.
